# Экраны фронтенда и данные для них

Ответственная: Саша. Какие данные нужны каждому экрану и из какого эндпоинта
фронт их берёт.

Макеты: https://www.figma.com/design/6STtRl8uzfEyVRKILRomJj

Источник правды по эндпоинтам — `API.md`, по атрибутам — `attributes.md`,
по решениям — `docs/HANDBOOK.md`, раздел 8. Этот файл контракт не меняет. Пункты
с пометкой *(PR)* опираются на решения из PR `docs/api-design-sync`: по ним
рисуем, код пишем после мержа.

## Общее

- Все списки (категории, цвета, стили, сезоны) фронт строит из `GET /attributes`,
  в коде значения не хардкодим.
- Подписи на карточках вещей — названия категорий из справочника: «Верх», «Низ»,
  «Платье», «Верхняя одежда», «Обувь», «Аксессуары».
- Карточек в комплекте столько, сколько пришло в `items`, а не пять фиксированных
  ячеек. В макете пример на пять вещей.
- Ошибки показываем текстом из `detail`. У `422` `detail` — список ошибок по полям,
  его разбираем и показываем под нужными полями.
- На любой `401` чистим токен из `localStorage` и отправляем на экран входа.

## 1. Вход и регистрация — к 12 октября

| Экран | Данные | Эндпоинт |
|---|---|---|
| Вход | email, пароль → токен и пользователь | `POST /auth/login` |
| Регистрация | имя (необязательно), email, пароль → токен и пользователь | `POST /auth/register` |
| Запуск приложения | есть ли токен, пройден ли онбординг | `GET /users/me` → `onboarding_completed` |

Логика запуска:

- токена нет или пришёл `401` → экран входа;
- `onboarding_completed: false` → онбординг;
- иначе сразу «Сегодня».

Ошибки: `409` на регистрации — «почта занята», `401` на входе — «неверная почта
или пароль». Имя необязательное, до 50 символов: нет имени — приветствие без
него *(PR)*.

## 2. Онбординг — к 12 октября

| Шаг | Данные | Эндпоинт |
|---|---|---|
| Стиль (можно пропустить) | один из трёх: Спортивный, Повседневный, Деловой | `GET /attributes` → `style` |
| Цвета (можно пропустить) | «Люблю носить» и «Не ношу», один цвет не может быть в обоих | `GET /attributes` → `color` |
| Город (пропустить нельзя) | название, геолокация или подсказка из списка | `GET /geo/cities` *(PR)* |
| Готово | `city` + `preferences` одним запросом | `PATCH /users/me` |

- Онбординг пройден, когда указан город *(PR)*. На шаге города кнопки
  «Пропустить» нет.
- `preferences` уходит целиком: `style`, `liked_colors`, `disliked_colors`.
- `400` «Город не найден» показываем под полем города и остаёмся на шаге.

## 3. «Сегодня» — к 9 ноября

| Блок экрана | Поле | Эндпоинт |
|---|---|---|
| Погода: город, температура, «ощущается как», ветер, осадки в %, иконка | `weather.*` | `GET /outfit/today` |
| Комплект с фото | `items[]` → `category`, `name`, `photo.url` | `GET /outfit/today` |
| «Почему этот комплект» | `explanation` | `GET /outfit/today` |
| Недостающая вещь | `missing` | `GET /outfit/today` |
| «Другой вариант» и переключение «Вариант 1 из 3» | до 3 вариантов в день | `POST /outfit/today/regenerate` *(PR)* |
| «Нравится», «Надет сегодня» | `rating`, `worn` | `POST /outfit/{id}/feedback` (этап 4) |

- Иконка погоды — по `condition`: `clear` / `cloudy` / `rain` / `snow`.
- Вероятность осадков показываем в процентах *(PR)*.
- Между вариантами дня переключаемся **свайпом влево-вправо по сетке комплекта**
  и кнопкой «1 из 3». Свайп за последний вариант — то же, что «Другой вариант»
  (`POST /outfit/today/regenerate`), если лимит не исчерпан.
- Нет другого варианта — `409`, показываем сообщение, лимит не тратится *(PR)*.
- После отметки «Надет» переключать и перегенерировать варианты нельзя: кнопки
  неактивны, пока отметку не сняли *(PR)*.
- Партнёрский товар показываем на месте недостающей вещи, в пустой карточке.
- `400` «Укажи город в профиле» → в онбординг; `502` → сообщение и «Повторить».
- Пока идёт запрос — скелетоны на месте погоды и комплекта.
- Пустой гардероб — тот же экран с `explanation` и кнопкой «Добавить вещь».

## 4. Гардероб — к 26 октября

| Экран | Данные | Эндпоинт |
|---|---|---|
| Сетка вещей | фото, `name`, `category`, `color` | `GET /items` |
| Фильтры | чипы по категории, кружки по цвету | `GET /items?category=…&color=…` |
| Поиск по названию | — | фильтруем на фронте по `name` |
| Пусто | `total: 0` | `GET /items` |
| Карточка вещи | все поля Item | `GET /items/{id}` |
| Изменить / удалить | — | `PATCH /items/{id}`, `DELETE /items/{id}` |
| Добавление: фото | JPEG, PNG, WebP до 10 МБ → `photo_id` | `POST /photos` |
| Добавление: форма | название, категория, цвет, теплота (обязательно), стиль, сезон, защита от осадков | `POST /items` |
| Предзаполнение (этап 4) | только `category` и `color` с уверенностью | `POST /items/recognize` |

- Материала нет. Сезоны — Лето / Демисезон / Зима, можно несколько.
- `413` / `415` при загрузке фото — понятный текст под кнопкой загрузки.
- Распознавание медленное — экран «распознаём» со спиннером.

## 5. История — к 23 ноября (этап 4)

| Экран | Данные | Эндпоинт |
|---|---|---|
| Список прошлых комплектов | Outfit с `feedback` | `GET /outfit/history?from=…&to=…` |
| Прошлый день | Outfit за дату | из того же списка |

## 6. Партнёрские товары — к 7 декабря (этап 5)

Карточка товара в пустой ячейке комплекта: фото, магазин, название, цена,
кнопка «В магазин», пометка «Реклама». Поля — из `missing[].suggestions`
(`image_url`, `shop`, `name`, `price`, `url`).

## Идеи на будущее

Есть в макетах, в коде не делаем, на защите показываем как план развития.
В Figma такие экраны подписаны «Идея на будущее».

- Цветотип по селфи и палитра под внешность.
- Замена одной вещи в комплекте.
- «Идея дня» и блок «Попробуйте что-то новое».
- Уведомления («Когда присылать комплект»).
- Выбор языка.
- «Где чаще одеваетесь».
- Статистика носки по вещи.
- Календарь в истории (в MVP — список комплектов).
