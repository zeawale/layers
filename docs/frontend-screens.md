# Экраны фронтенда и данные для них

Ответственная: Саша. Сверка макетов с `API.md` — какие данные нужны каждому экрану
и из какого эндпоинта фронт их берёт.

Макеты: https://www.figma.com/design/6STtRl8uzfEyVRKILRomJj

Источник правды по эндпоинтам — `API.md`. Этот файл ничего в контракте не меняет:
всё, чего в `API.md` нет, вынесено в конец как **предложения** — их обсуждаем отдельно.

## Как экраны ложатся на справочник

В макетах вещи комплекта подписаны «слоями». Это те же категории из `attributes.md`,
просто с другими подписями:

| Подпись в макете | `category` |
|---|---|
| Верхний слой | `outerwear` |
| Основа | `top` (или `dress`) |
| Низ | `bottom` |
| Обувь | `footwear` |
| Аксессуар | `accessory` |

Все списки (стили, цвета, сезоны, категории) фронт строит из `GET /attributes`,
в коде значения не хардкодим.

---

## 1. Вход и регистрация — к 12 октября

| Экран | Данные | Эндпоинт |
|---|---|---|
| Вход | email, пароль → токен и пользователь | `POST /auth/login` |
| Регистрация | email, пароль → токен и пользователь | `POST /auth/register` |
| Запуск приложения | Есть ли токен, пройден ли онбординг | `GET /users/me` → `onboarding_completed` |

Логика запуска:

- токена нет или на любой запрос пришёл `401` → чистим токен, экран входа;
- `onboarding_completed: false` → онбординг;
- иначе сразу «Сегодня».

Ошибки показываем текстом из `detail`: `409` на регистрации — «почта занята»,
`401` на входе — «неверная почта или пароль».

## 2. Онбординг — к 12 октября

| Шаг | Данные | Эндпоинт |
|---|---|---|
| Стиль | Список стилей | `GET /attributes` → `style` |
| Цвета | Список цветов (любимые / не ношу) | `GET /attributes` → `color` |
| Город | Название города | — |
| Готово | `city` + `preferences` одним запросом | `PATCH /users/me` |

- `preferences` уходит целиком: `style`, `liked_colors`, `disliked_colors`.
- `400` «Город не найден» показываем под полем города и остаёмся на шаге.

## 3. «Сегодня» — к 9 ноября

| Блок экрана | Поле | Эндпоинт |
|---|---|---|
| Погода: город, температура, «ощущается как», ветер, осадки, иконка | `weather.city`, `temp_min`/`temp_max`, `feels_like`, `wind_speed`, `precipitation`, `condition` | `GET /outfit/today` |
| Комплект по слоям с фото | `items[]` → `category`, `name`, `photo.url` | `GET /outfit/today` |
| «Почему этот комплект» | `explanation` | `GET /outfit/today` |
| Нет подходящей вещи | `missing` | `GET /outfit/today` |
| Кнопка «Другой вариант» | новый Outfit | `POST /outfit/today/regenerate` |
| «Нравится» | `rating: like` | `POST /outfit/{id}/feedback` (этап 4) |

- Температура крупно — `temp_max`, под ней диапазон и «ощущается как».
- Иконка погоды выбирается по `condition`: `clear` / `cloudy` / `rain` / `snow`.
- `400` «Укажи город в профиле» → в онбординг; `502` → сообщение и кнопка «Повторить».
- Пока идёт запрос — заглушки-скелетоны на месте погоды и комплекта (есть в макетах).
- Пустой гардероб — тот же экран с `explanation`, плюс кнопка «Добавить вещь».

## 4. Гардероб — к 26 октября

| Экран | Данные | Эндпоинт |
|---|---|---|
| Сетка вещей | фото, `name`, `category`, `color` | `GET /items` |
| Фильтры | чипы по категории, кружки по цвету | `GET /items?category=…&color=…` |
| Поиск по названию | — | фильтруем на фронте по `name` (пагинации нет, вещей десятки) |
| Пусто | `total: 0` | `GET /items` |
| Карточка вещи | все поля Item | `GET /items/{id}` |
| Изменить / удалить | — | `PATCH /items/{id}`, `DELETE /items/{id}` |
| Добавление: фото | файл → `photo_id` | `POST /photos` |
| Добавление: форма | `name`, `category`, `color`, `warmth`, `style`, `season`, `water_resistance` | `POST /items` |
| Предзаполнение (этап 4) | `category`, `color` + `confidence` | `POST /items/recognize` |

- В форме поля из справочника, сезоны — `summer` / `demi` / `winter`.
- `413` / `415` при загрузке фото — понятный текст под кнопкой загрузки.
- Распознавание медленное — показываем экран «распознаём» со спиннером.

## 5. История — к 23 ноября (этап 4, черновик)

| Экран | Данные | Эндпоинт |
|---|---|---|
| Календарь носки | даты комплектов, `feedback.worn`, `feedback.rating` | `GET /outfit/history?from=…&to=…` |
| Список последних комплектов | Outfit целиком | `GET /outfit/history` |
| Прошлый день | Outfit за дату | берём из того же списка |

## 6. Партнёрские товары — к 7 декабря (этап 5, черновик)

Карточка товара в макете: фото, магазин, название, цена, кнопка «В магазин».
Всё это есть в предложенном формате `missing[].suggestions` (`image_url`, `shop`,
`name`, `price`, `url`).

## Что поправить в макетах под справочник

- Онбординг, стиль: в макете 6 стилей и мультивыбор → делаем **один** из трёх
  (`sport`, `casual`, `business`).
- Онбординг, цвета: палитра строится из справочника (16 цветов), а не из макета.
- Форма вещи: поле «Материал» убираем, сезоны — три вместо четырёх, добавляем
  «Теплоту» (1–5) и «Защиту от осадков».
- Главный экран: счётчик «Вариант 1 из 3» убираем — в API вариантов не ограничено.
- Причины-чипы под объяснением («Погода», «Ваш стиль») и заголовок комплекта —
  в API их нет, на первом этапе не показываем (см. предложения).

## Предложения к API (нужно обсудить)

1. **Имя пользователя.** На главном экране «Доброе утро, Саша». Предлагаю
   необязательное `name` в `POST /auth/register` и `PATCH /users/me`. Если не
   делаем — пишем просто «Доброе утро».
2. **Вероятность осадков.** В макете «осадки 40%», в API — миллиметры. Можно
   добавить `precipitation_probability` (Open-Meteo его отдаёт) или показывать мм.
3. **Причины в объяснении.** Короткие метки к `explanation` (`["weather", "style"]`),
   чтобы показывать чипы «Погода», «Ваш стиль». Необязательно.

## В макетах, но не в плане (идеи на будущее)

Эти экраны есть в Figma как идеи развития продукта, в MVP их не делаем.
На защите — раздел «перспективы».

- Анализ внешности по селфи и подбор палитры (цветотип).
- Примерка образа на фото пользователя.
- Замена одной вещи в комплекте с новым объяснением.
- Блок «Попробуйте что-то новое» и экран смелого варианта.
- Статистика вещи в карточке (сколько раз надевали, с чем сочетается).
