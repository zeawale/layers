# Layers

Веб-сервис персональных рекомендаций одежды. Пользователь заносит вещи в
цифровой гардероб, сервис каждый день предлагает комплект по прогнозу погоды,
стилевым предпочтениям и истории оценок — и объясняет свой выбор словами.
Если подходящей вещи нет, предлагает товар партнёрского магазина.

Учебный проект по предмету «проектная деятельность», СПбГУТ им. Бонч-Бруевича.

## Запуск

Нужен установленный Docker Desktop.

```bash
git clone <адрес репозитория>
cd layers
cp .env.example .env
docker compose up
```

Что должно получиться:

- бэкенд — http://localhost:8000
- документация API (Swagger) — http://localhost:8000/docs
- фронтенд — http://localhost:5173

На главной странице фронта должна появиться зелёная плашка «Бэкенд на связи».
Если она красная — бэкенд не поднялся, смотри логи: `docker compose logs backend`.

Первый запуск долгий: качаются образы, ставятся зависимости и модели
распознавания фото — в сумме около 15 минут и 2,5 ГБ на диске. Дальше секунды.
Пересборка нужна только после правки `requirements.txt`, и модели при этом
заново не качаются. Docker Desktop нужно хотя бы 4 ГБ памяти (Settings →
Resources): распознавание держит модели в памяти, около 2 ГБ.

Первое распознавание фото после старта бэкенда идёт секунд 20 — модели
загружаются в память. Дальше несколько секунд на фото.

### Полезные команды

```bash
docker compose up -d          # запустить в фоне
docker compose logs -f backend  # смотреть логи бэкенда
docker compose down           # остановить
docker compose down -v        # остановить и снести базу вместе с данными
docker compose build backend  # пересобрать после правки requirements.txt
```

### Миграции базы

Таблицы создаёт Alembic. В Docker Compose бэкенд при старте сам выполняет
`alembic upgrade head`, руками ничего запускать не надо.

Поменяла модель в `backend/app/models/` — добавь миграцию в том же PR:

```bash
docker compose exec backend alembic revision --autogenerate -m "что поменялось"
```

Файл появится в `backend/alembic/versions/`. Открой его и проверь глазами:
autogenerate не всё видит сам (например, переименование поля он поймёт как
удаление и добавление).

### Без докера

Если докер капризничает, бэкенд и фронт можно поднять руками — но база всё
равно нужна, проще оставить её в докере.

```bash
# бэкенд
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload

# фронтенд
cd frontend
npm install
npm run dev
```

```
layers/

│   ├── alembic/          миграции базы

│   ├── HANDBOOK.md       как работаем: гит, ревью, сроки, принятые решения
```

## Что уже работает

Какие разделы `API.md` уже есть на бэке, видно по отметке «Бэк готов» рядом
со статусом раздела. Попробовать руками — Swagger на http://localhost:8000/docs.
Рекомендации пока собирает временная заглушка вместо движка: она пишет об этом
в объяснении комплекта.

Письма сброса пароля без настроенной почты не уходят, а печатаются в лог:
`docker compose logs backend` (см. `.env.example`, раздел про почту).

## Секреты

Всё, что нельзя показывать, живёт в `.env` — он в `.gitignore` и в репозиторий
не попадает. Когда добавляешь новую переменную, добавь её и в `.env.example`
с безопасной заглушкой, иначе у остальных ничего не заведётся.

## Как работаем с гитом

Подробно, с командами по шагам, — в [docs/HANDBOOK.md](docs/HANDBOOK.md).

- `main` защищён, напрямую в него не пушим.
- Ветка на задачу: `feat/wardrobe-list`, `fix/login-error`.
- Изменения попадают в `main` только через pull request с ревью.
- Перед тем как открыть PR, подтяни свежий `main`: `git pull --rebase origin main`.
